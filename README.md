# AI Work OS

面向个人程序员、支持多项目和多仓库的智能工作平台。

平台管理工作目标、任务流程、权限、知识和验收；Codex、OpenCode 等 Agent 承担步骤内部的执行；优化中心依据可追溯的结果持续改进 Skill、知识和工作流。

## 外部 Skill 引用

在「能力与知识」中注册本机目录，递归扫描包含 SKILL.md 的 Skill，并在创建任务时以引用 ID 选择使用。不复制外部目录到项目或 Worktree；任务执行准备时读取指令并冻结该次运行的最小审计快照。来源改变后，新运行使用最新指令，旧运行不静默升级。辅助 scripts/、references/ 等文件仍留在原路径，访问受执行器沙箱约束。详见 [外部 Skill 目录引用](docs/外部Skill目录引用.md)。

## 开发运行

需要 Node.js 22.13 或更高版本以及 Git。

```sh
npm ci
npm run check
npm run dev
```

开发页面为 http://127.0.0.1:5173，API服务为 http://127.0.0.1:4310。生产方式在 `npm run build` 后执行 `npm start`，访问4310端口。

首次启动自动生成本机访问令牌，终端显示令牌文件位置；将该文件内容填入连接页。令牌只存于浏览器当前会话，不提交到仓库。默认运行数据在本机 `%LOCALAPPDATA%/AIWorkOS`（非Windows为 `~/.local/share/AIWorkOS`），可用 `AI_WORK_OS_DATA_DIR` 指定独立数据目录。不要将活跃状态库放进仓库或同步目录。

当前支持任务、项目、人工执行、Codex开发与只读诊断流程至交付验收。Codex开发任务需在项目中授权隔离工作区修改并配置测试程序及JSON参数数组；程序直接执行，不经过Shell。Windows建议填写exe程序路径（例如Node），而不是cmd脚本。测试程序使用本机用户权限，应来自受信任项目。运行产物可在交付页下载，下载时校验摘要。

使用 `npx tsx scripts/smoke-agent.ts` 可显式调用本机Codex进行最小真实执行检查，需要已配置登录态，会使用模型调用额度；该命令不在CI自动执行。

“目标与计划”支持目标、父子任务、依赖、日期计划、版本化编辑及按日期范围回顾；依赖任务未验收时不能启动，父任务验收要求全部子任务验收。“故障诊断”支持带来源的证据、假设修订、支持/反证引用和结论报告。先创建诊断任务、登记证据，再从工作台准备并启动；诊断需要仓库与Agent授权，使用只读沙箱，不运行开发测试命令。没有经用户验证的因果实验时不能生成确认根因结论。可用 `npx tsx scripts/smoke-agent.ts --diagnosis` 显式验证真实诊断调用。

“能力与知识”入口支持Skill、带来源的知识及工作流版本管理，发布后可在创建任务时选择，启动时冻结实际内容。Agent暂停并确认停止后可在原Worktree恢复；暂停后人工修改代码，需要先重新规划，保留旧计划并重新执行验证。恢复使用平台保存的步骤结果重建上下文，当前不依赖执行器原会话恢复。

“优化中心”支持失败聚类、Skill候选、不可变案例集、基线/候选成对试跑、真实产物评估、限定项目灰度、人工发布与回滚。留出案例不能复用优化依据中的输入，不能用重复运行增加独立样本数。默认需要20个留出案例，人工试验策略可显式调整；验证通过数不等同于业务验收或通用收益。试跑会调用模型并执行案例中的可信本机测试命令，需在页面中明确授权；Worktree提供代码目录隔离，不是网络或进程沙箱。

任务可以选择固定资源版本，或“跟随发布版本”。发布和回滚只影响之后启动的跟随任务，已有运行保留具体内容快照。低风险自动策略默认关闭，仅支持执行正文、工作流和来源集合不变的更新，要求已知模型配置、至少20个留出案例，并先经过选定项目的灰度验收。周期分析也默认关闭，只在本机服务运行期间处理，漏触发合并，不自动启动成对试跑。

“项目与仓库”显示执行器版本、根配置中的模型/推理参数及配置摘要；执行时显式传递模型参数并检查根配置漂移。可用 `AI_WORK_OS_CODEX_MODEL` 指定平台执行模型。配置模型名称不代表服务端权重可完全重放。

Windows控制服务异常退出后，可依据Worker持久停止凭据补收步骤和交付，或保存检查点并暂停；缺少证明时保留写锁。执行台提供人工核对入口，要求检查遗留进程和外部影响，后端复核批次、代码摘要与已知进程；人工核对后的恢复重新验证全部步骤。同一数据目录只允许一个存活控制服务。适用范围与限制见[运行恢复与进程管理](docs/运行恢复与进程管理.md)。

OpenCode、完整跨平台/工具服务恢复、Agent主动提交流程提案、完整权限/日志/产物治理与最终UI验收仍在实现。[代码结构与实现进度](docs/代码结构与实现计划.md)列出完整剩余范围。设计稿中的容量、性能和评估阈值均为拟定目标，不代表实测结果。

可通过 `AI_WORK_OS_PORT` 设置本机服务端口（默认4310），便于在独立数据目录运行验证实例。
