# AI Work OS 自适应工作流 V2：实现与使用说明

> 2026-11-11；Linux + Node.js 22；实现状态：功能分支、待完整集成评审  
> 架构基线：[V2.1 自适应原子能力架构](./AI-Work-OS-自适应原子能力架构方案-v2.1.md)

## 1. 本分支实现范围

### 原子能力与执行配置

- Capability：ID/语义版本、业务描述、输入/输出 JSON Schema 安全子集、副作用类型、标签、Profile 引用、作用域和候选/验证/发布/撤销状态。
- ExecutionProfile：Codex Agent、项目授权的程序或测试命令、人工输入、平台内置执行器；可配置 model、外部 Skill 引用、MCP grants 声明、工作区策略、超时、成本预算字段。
- 未发布能力不可被编排执行；候选能力可更新 Schema、描述、执行配置；已发布版本不被原地覆盖。
- 系统启动时幂等初始化 core.analyze、core.design、core.implement、core.test、core.review、core.collect、core.hypothesize、core.verify、core.conclude、core.deliver 等平台核心能力。
- 自适应运行冻结能力、Profile 和外部 Skill 的 SKILL.md 指令。原始目录引用保持不变，脚本和附件不会自动复制或获取更高权限。

### Skill 导入与候选生成

- 注册 Linux 绝对目录、递归扫描 SKILL.md、跳过符号链接、检查目录越界、识别缺失来源。
- 提供快速确定性候选草案，以及通过本机已授权 Codex 分析 Skill 生成候选能力的路径。
- 所有自动生成结果均为 candidate；输入输出是推断的候选契约，需用户核查、绑定 Profile、验证后才能发布。
- 内容摘要变化后拒绝复用过期的契约，不擅自执行辅助脚本。

### Knowledge Hub

- 用户创建全局、项目、能力、任务知识；设置来源、标签、适用能力、草稿/发布/撤销和版本。
- KnowledgeBinding 支持 required、on-demand、optional；必需知识不可用时拒绝执行。
- 授权范围过滤后进行简单的全文匹配及绑定检索，记录检索摘要、知识版本和返回引用。
- 已发布知识版本不能被静默修改；Agent 推断不自动晋升为全局事实。

### 智能编排、观察与重规划

- Codex Planner 根据任务、能力目录与知识生成执行 DAG 和 ObservationPolicy。
- 无可用模型时提供明确标注的确定性标准工作流，不将模板冒充 AI 规划。
- DAG 编译校验：能力/Profile 是否发布、Schema 绑定、依赖无环、唯一交付节点、代码写入后的测试和审查门槛、权限和副作用边界。
- Barrier 检查点阻断相关后继工作；Advisory 检查点可以晚于就绪业务节点评估；成功/失败事件都可触发观察。
- Evaluator 产生 CONTINUE、REPLAN、RETRY、WAIT_INPUT、WAIT_APPROVAL 或 STOP。必要时 Replanner 提交新的 PlanRevision，旧证据、执行和版本历史保留。
- 重规划上限为 5 个版本，已完成结果只有依赖与配置完全不变时才能安全复用。

### 事件驱动的单能力执行

- 每个 CapabilityInvocation 独立获取输入、权限、知识与 Skill 快照，执行完成后释放 Agent 进程。
- SQLite 为状态权威；本机事件唤醒调度，10 秒周期扫描为漏通知和控制器恢复提供补偿。
- 审计事件、Invocation、PlanRevision、Knowledge 查询与 SideEffectLedger 形成可追溯链路。
- 写入型能力使用独立 Git Worktree；项目测试使用明确授权的项目测试命令。
- 有写入副作用的运行中断或失败会进入 uncertain/reconciling，**不会盲目自动重试**；需要人工核对。
- 控制服务重启时对运行中调用执行保守恢复；对已运行的副作用不能凭未收到 ACK 推断执行失败。

## 2. UI 与操作方式

在左侧“自适应工作流”页：

1. 创建和发布 ExecutionProfile。
2. 扫描外部 Skill，选择确定性草案或使用 Codex 智能分析；绑定执行配置并验证发布 Capability。
3. 新建全局/项目/能力/任务知识，发布后按需绑定到 Capability。
4. 在工作台创建任务，指定项目、目标和验收条件。
5. 选择任务，调用 Codex Planner 或标准流程，审查 DAG 节点、输入绑定和观察点。
6. 验证工作流，通过后确认下发，查看节点、观察结果与事件历史。
7. 人工能力可提交符合 Schema 的输出；交付后由用户验收。失败的外部副作用应先核对，不能盲重试。

## 3. 主要 API

所有接口均需要现有 Bearer 本地访问令牌和来源校验，V2 路径前缀为 /api/v2。

| 资源 | API |
| --- | --- |
| 能力 | GET/POST /capabilities；POST /capabilities/:id/candidate、/validate、/publish、/revoke |
| 执行配置 | GET/POST /profiles；POST /profiles/:id/publish |
| 知识 | GET/POST /knowledge；POST /knowledge/:id/publish、/revoke；POST /knowledge/search、/knowledge-bindings |
| 外部 Skill | GET/POST /skill-sources；POST /skill-sources/:id/scan；GET /external-skills；POST /skill-candidates |
| 工作流 | POST /tasks/:id/compose；POST /tasks/:id/standard-plan；POST /workflows/validate |
| 运行 | GET/POST /adaptive-runs；GET /adaptive-runs/:id、/events、/invocations、/plan-revisions、/side-effects |
| 人工控制 | POST /adaptive-runs/:id/manual/:nodeId/complete、/retry、/accept、/cancel、/observations/:checkpointId/decision、/reconcile/:nodeId |

详细请求结构以 packages/adaptive 的 Zod Schema 为准。Planner 输出的 DAG 需要先审核、校验，再调用 POST /api/v2/adaptive-runs 下发。

一个简化手动工作流：

~~~json
{
  "nodes": [
    {"id": "collect", "capabilityRef": "core.collect@1.0.0",
     "dependsOn": [], "inputs": {"objective": "Collect diagnostics"}, "bindings": {}},
    {"id": "deliver", "capabilityRef": "core.deliver@1.0.0",
     "dependsOn": ["collect"], "inputs": {"objective": "Summarize findings"}, "bindings": {}}
  ],
  "observations": [
    {"id": "evidence-check", "afterNode": "collect",
     "on": ["succeeded", "failed"], "barrier": true,
     "question": "Is the evidence sufficient?", "maxInvocations": 1}
  ],
  "rationale": "Analyze evidence before delivering"
}
~~~

## 4. 当前尚不能视为生产级完成的部分

这是一份面向 V2.1 的**可运行主干实现**，但以下边界必须保留：

1. **MCP 逐执行配置的权限隔离尚未实现**。MCP grants 虽可存储，当前对非空 grants **拒绝执行**，防止无意继承用户的全局 MCP 权限。
2. **真实 Codex 模型、工具和 Linux 控制器崩溃的端到端 Smoke 测试尚未完成**。CI 主要验证类型、模拟执行器、DAG、知识、安全门槛和前端构建；CI 通过不代表真实模型/安全部署已验证。
3. **并行 DAG、完整条件分支、分布式调度、cgroup v2 进程 containment 尚未完成**。当前单机按就绪顺序逐节点派发。
4. **写入中断后的自动安全续跑未完成**。保守进入 reconciliation，由人确认遗留进程与外部副作用，不会自动重复执行有危险的写入。
5. **知识检索先采用关键词/绑定机制**，向量索引、分块重排、高级知识冲突治理和团队 ACL 尚未完成。
6. **AI 生成的候选能力仍需人审与契约验证**；目前允许记录人工验证依据，自动化沙箱契约测试和更强的发布门槛仍需补齐。
7. **新 V2 AdaptiveEngine 与旧 Supervisor 分别维护运行状态**，两套流程不能混用；需要明确迁移和跨系统验收。
8. **高级监控分析与自动优化大屏后置**。已保留基础事件、Invocation、知识访问引用及 SideEffectLedger。
9. **外部 Skill 辅助脚本、references、assets 不自动挂载**，仅将 SKILL.md 指令冻结在运行快照。
10. 当前还需负载测试和安全评审，尤其是多工作流、模型超时、存储增长与工作区锁。

## 5. Linux 集成验收清单

- npm ci && npm run check 在 Ubuntu Node 22 上通过。
- 真实 Codex：Planner → DAG 校验 → 只读能力 → Worktree 写入 → 项目测试 → 审查 → 交付，隔离环境人工验收。
- 异常注入：子进程崩溃、控制器中断、失去 ACK、Skill 文件变化、必需知识撤销、工作区漂移、异常的 MCP 授权声明。
- 校验 Barrier / Advisory、失败触发评估、REPLAN 的历史保留、有限重试和副作用核对。
- 检查日志和工件访问不会泄漏本机凭据，且取消/恢复不会悄悄提交、发布或重复危险外部动作。

**不要将本分支的“功能代码存在”或“单元测试通过”表述为已实现 V2.1 的所有生产保障。**
