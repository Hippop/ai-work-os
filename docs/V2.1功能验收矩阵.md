# AI Work OS V2.1 功能验收矩阵（Linux）

> 2026-11-11；此表是工程交付核查表，不是全部生产能力已验证的声明。
> 当前目标分支：main；PR #1–#4 已合并；本文件按主分支后续提交持续更新。
> CI 标准：Ubuntu / Node.js 22 / npm ci && npm run check。

状态定义：

- **实现+CI**：代码与模拟/单元回归检查已具备；尚不表示真实外部依赖经过端到端验收。
- **目标机待验**：存在实际集成路径，但需要用户授权的 Linux、Codex/MCP、真实内核/凭据或故障注入。
- **部分实现**：功能可用的一部分，剩余子功能未闭环。
- **未实现**：不能向用户宣称该能力可用。

## 2026-11-11 直接合入 main 的增量

- **MCP 写工具审批**：新建 `McpWriteService` 与 `/api/v2/mcp-write-intents` API，单独于 Agent 的自动 MCP 只读授权。请求记录工具/项目/精确参数摘要；用户先审批再明确执行；默认只支持经 `AI_WORK_OS_MCP_WRITE_ALLOW_HOSTS` 白名单允许的 HTTPS Streamable HTTP 端点。超时或回执丢失时标记 uncertain，不能自动重复执行。服务器 stdio 写入和 OAuth 暂未开放。
- **费用预留**：ExecutionProfile 可指定 `billing`（输入/输出单价及预留 token），运行可传 `budgetUsd`。SQLite 事务下为调用预留费用，完成后据返回 token 数结算；缺失用量和超预留会阻断后续付费调用，并允许用户核对真实 token。估算成本不等同于供应商账单，也不能物理中止已开始的调用来保证单次硬上限。
- **入口与自动化检查**：自适应工作台增加写操作审批账本、费用输入与报表；单元和 HTTP 协议模拟测试检验精确授权、单次执行、安全恢复、用量账本与主 API 鉴权。

## 生产准备的阻断事项

1. 在受控 Linux 机器上安装并验证 Codex 与各 MCP Server；确认审批、沙箱、工具白名单、账号与项目配置不会越权。
2. 使用显式 opt-in 的 smoke 流程验证真实模型对代码仓库的写入、测试、审查和交付，不向生产仓库默认执行写操作。
3. 在已委派 cgroup v2 的测试环境进行 OOM、子进程逃逸、controller restart 和多次 kill，证明失败保持可核对且不会重复副作用。
4. 逐权限评估真实 MCP 工具，特别是工具虽声称只读但可能触发数据导出或远程更改的情况。
5. 对 Profile/Skill/Knowledge 版本冻结以及运行中变更做场景化审计；把原工作流与 V2 新路径的迁移/回滚演练完成。
6. 针对知识泄漏、模型提示注入、密钥进入子进程环境、工件越界、日志保留/清理执行安全评审。
7. 在 API/CLI 中完成真实运行的性能、token 用量、失败率、成本与恢复评估，形成交付签字。
