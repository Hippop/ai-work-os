# 代码结构与实现计划

更新：2026-11-09。产品要求以[完整设计稿](AI-Work-OS-设计稿-v1.0.md)为准。本文件记录实际代码与剩余工作，不能用已通过的局部测试推断整个产品已完成。

## 代码结构

```text
apps/server/app.ts           HTTP边界、鉴权、参数校验、静态页面服务
apps/server/index.ts         本机启动、运行目录、令牌与生命周期
apps/web/src/main.tsx        工作台、执行台、项目、优化概览
apps/web/src/style.css       桌面/移动布局
packages/domain/index.ts    领域类型、输入契约、状态转换
packages/persistence/       SQLite事务、实体、事件、幂等记录与outbox
packages/workflow/          任务准备、运行控制、交付、业务验收
tests/workflow.test.ts      状态/幂等/持久化/HTTP集成验证
apps/worker/index.ts        独立执行进程，步骤协议和Agent调用
packages/runtime/          Codex适配、进程树控制、调度监督器
packages/workspace/        Worktree创建、代码摘要、变更导出
tests/runtime.test.ts      真实子进程、隔离、测试失败、取消与产物校验
scripts/smoke-agent.ts     显式运行的真实Codex端到端冒烟检查
packages/resources/       不可变Skill/知识/工作流版本、发布/撤销、上下文冻结与图校验
apps/web/src/ResourceManager.tsx  资源管理页面
apps/web/src/PlanEditor.tsx       暂停后的计划修订与人工修改接纳
packages/planning/        目标、父子/依赖关系、日期范围汇总
packages/diagnosis/       证据/假设版本、证据引用与因果结论校验
apps/web/src/PlanningBoard.tsx   目标、任务编辑与回顾页面
apps/web/src/DiagnosisBoard.tsx  假设—证据工作区与诊断报告
packages/optimization/index.ts  分析、提案、案例、试跑、评估、发布与周期调度
packages/optimization/rollout.ts  项目灰度、名额、验收观察和晋级/停止
apps/web/src/OptimizationBoard.tsx  优化中心完整操作流程
apps/web/src/RuntimeStatus.tsx  本机执行器和根配置状态

```

前端仅通过HTTP操作领域模型；控制服务唯一写库。实体JSON暂存在统一实体表中，事件、幂等和outbox独立建表；这是当前实现选择，设计稿中的完整关系约束尚待后续迁移。需要先补版本迁移机制，再扩展表结构。

下一步把前端拆为页面、表单、运行详情组件及独立API客户端；领域契约进一步拆分，避免单个入口文件随产品增长。

## 当前可用

- 创建任务、绑定已有Git项目，验证目标与验收清单。
- 人工任务执行准备、启动、暂停/恢复/取消、提交成果、接受/退回。
- 区分运行成功和业务验收；退回增加任务版本，历史运行保留。
- 运行状态机、事务追加事件、启动幂等、防止任务同时运行、准备摘要失效检查。
- 本机令牌鉴权、来源检查、输入校验、数据库持久化与重开恢复。
- 工作台、执行台、项目设置、真实样本计数与响应式布局。
- Codex可执行文件探测、独立Worker、outbox派发、运行隔离Worktree、六步骤固定开发流程。
- 项目级显式Agent授权和测试命令配置，运行时间预算，结构化输出，确定性测试，代码/产物摘要和下载校验。
- 等待进程树停止后再取消/释放工作区；重启后不明运行进入核对状态，不盲目重跑。
- 已通过一次真实Codex最小开发任务：隔离修改、测试、审查、交付，详见验证记录。
- 确认停止后的Agent恢复：复用原Worktree，重建已完成步骤上下文，保留中断尝试历史和各次执行产物。
- 人工修改后的代码漂移检查、暂停期间修订有向无环图、旧图保存和全量验证失效；新步骤可在受限能力集合内增加。
- Skill/知识/模板的候选创建、人工发布、撤销和版本指针；资源选择、作用域过滤、知识来源要求、上下文大小限制及运行内容快照。
- 目标和项目关联、父子任务/依赖循环检测、依赖启动门槛、父任务验收门槛、任务修订历史、日期计划与验收事实汇总。
- 只读诊断五步骤、证据快照、假设与反证、假设修订历史、确认/可能/证据不足三种结论及诊断报告下载。
- 诊断结论引用必须属于该任务的输入证据，确认根因要求经用户核实的因果实验；新增证据不改变已启动运行的快照。
- 失败聚类、依据失败轨迹生成Skill候选、固定独立案例集、基线/候选真实成对执行及产物摘要校验。
- 配对输入包含仓库基线、非目标资源、模型参数、根配置摘要和Node/操作系统信息；重复运行和已用于优化的输入不能计作独立留出案例。
- 发布门槛含样本数、候选验证、预设留出集通过数收益及人工理由；灰度限定项目和未来任务数，经业务验收后晋级，失败后停止新采用。
- 跟随发布的资源绑定、固定运行快照、回滚指针、默认关闭的周期分析和受限低风险自动策略。
- Windows命令Job Object回收，控制服务单实例所有权、派发意图/租约、持久停止凭据、崩溃后幂等补收步骤及交付；证据不足时保留写锁。
- 人工核对入口：核对批次、代码摘要和已知进程，保存明确声明与依据；核对后重新验证全部步骤，保留历史。

Codex开发任务仅在本机探测成功、绑定仓库、项目显式授权并配置测试命令时允许启动；诊断同样要求本机执行器、仓库及授权，但只读且不运行开发测试命令。OpenCode尚未开放。Windows异常退出后的恢复以匹配停止凭据及已知进程退出为门槛；其他情况需人工核对，详见[运行恢复与进程管理](运行恢复与进程管理.md)。模板DAG按拓扑顺序串行执行。评估试跑需要用户授权可信本机测试，不能把Worktree视为网络沙箱；Docker客户端存在但本次检查时引擎未运行。当前优化指标是验证交付，通过数与业务验收分列，不支持伪造费用或通用收益声明。GitHub推送按用户要求在完整实现并验证后进行。
