# 首版断点修复与试用说明

2026-11-12；适用个人开发者、Linux 单机、本地 Bearer Token 服务。此版本可交测试人员验证，不代表真实供应商、内核故障和最终 UI 已完成验收。未创建正式 Release 或版本标签。

## 修复范围

| 原断点 | 当前行为 |
| --- | --- |
| 已取消旧运行复活、同任务多个活跃运行 | retry 限定失败/等待状态；校验任务版本、原项目配置及 V1/V2 互斥；取消终态不回写新任务状态 |
| V2 绕过前置任务和父子验收 | 下发与恢复校验前置任务；接受父任务要求子任务全部完成；已完成任务不能无版本变更重复执行 |
| 工件修改后仍可下载 | 执行结果固定工件 SHA-256；下载和接受交付均复核，缺失/改变/无原始摘要拒绝；审计包含脱敏工件摘要列表 |
| 阶段结果未传递 | Agent 接收全部已完成祖先输出、证据和工件引用，不注入无关并行分支；超过上下文预算显式报错 |
| 新 Worktree 缺少本地依赖 | 开发流程从首阶段固定同一 Worktree，可配置显式 setupCommand；并行节点共享一次初始化；初始化中断需人工核对 |
| 无法从 V2 页面停止与接管 | 按 Run 停止本机进程，等待执行记录收敛；提供暂停/取消/继续和逐调用核对；人工接纳工作区生成新计划修订，保留原失败证据，不重放已核对写入 |
| 主工作台无法打开 V2 运行 | 工作台按活跃状态与时间解析 V1/V2 运行，执行台列出 V2 入口并直达选中运行 |
| 配置问题直到执行中才暴露 | 独立预检及下发强制预检；已有项目可修改授权、测试、初始化命令；活跃运行期间拒绝修改 |

## 首次试用顺序

1. 安装 Node.js >=22.13 与 Git；克隆仓库后运行 npm ci、npm run check、npm run build、npm start。当前服务使用 tsx 加载源码，安装时需要开发依赖。
2. 读取启动日志指出的令牌文件，将内容填入本机连接页。使用受信任的一次性项目，仓库至少有一个提交。
3. 在项目页连接仓库并明确授权 Agent，配置测试程序、参数和可选初始化程序。已有项目展开运行配置表单编辑；空程序字段可移除对应命令。所有命令直接执行，不经过 Shell，具有本机用户权限。
4. 安装并认证 Codex 或 OpenCode。创建任务，在自适应工作流中选择执行器并生成标准流程，检查 DAG 与环境预检。预检不调用付费模型，CLI 版本检查不代表供应商登录、模型或 cgroup 已可用。
5. 下发后检查运行阶段、观察点、测试与审查证据，下载交付补丁/新增文件并人工验收。工件修改后应无法下载或接受。
6. 练习停止：停止并保留现场会阻止新派发、终止该 Run 的已知子进程并等待结果收敛。成功只读执行可继续；写入中断进入逐项核对，不能直接重试。
7. 核对所有遗留进程、外部影响、初始化依赖和代码。逐项提交依据后，必要时修复现场，再点击接纳现有工作区。页面提交的代码摘要必须与当前现场一致，接纳后重新分析、测试、审查与交付。外部写入结果未知时不能通过工作区接纳来绕过。

## 新增配置与 API

- Project.setupCommand：可选 {executable,args}。每个 V2 开发运行的新 Worktree 执行一次，使用同一任务剩余时间预算。不会复制 node_modules、虚拟环境、未跟踪配置或凭据。额外命令按原 authorizedCommands 授权。
- POST /api/v1/projects/:id/runtime-configuration：修改 allowAgent、testCommand、setupCommand、authorizedCommands；命令可用 null 清除；存在 V1/V2 活跃运行时拒绝。
- POST /api/v2/tasks/:id/preflight：请求 {plan}，返回 ready、checks；运行下发时同样强制预检。检测仓库 HEAD、授权、CLI 版本、测试/初始化及程序路径配置。
- GET /api/v2/run-index：脱敏的 V2 导航索引。
- POST /api/v2/adaptive-runs/:id/stop：{mode:"pause"|"cancel"}。运行中远程 MCP 写入不能通过停止本机进程来宣称已取消。
- POST /api/v2/adaptive-runs/:id/resume：继续已安全暂停、现场未变化的运行。
- GET /api/v2/adaptive-runs/:id/workspace：核对当前工作区摘要。
- POST /api/v2/adaptive-runs/:id/adopt-workspace：{expectedDigest,note}，note 至少20字。先停止并核对全部未确认调用；接纳已检查代码并生成新的审计修订，所有只读/测试/审查/交付节点重新验证。

## 兼容与边界

新增运行固定 taskRevision、projectDigest 与 artifactDigests。旧运行没有工件原始摘要时不会在下载时补算；应检查旧交付，结束旧运行后重新生成。不会自动迁移或重放旧外部动作。已有任务和历史数据保留 SQLite 原结构。

暂停与人工核对仍使用原任务墙钟时间预算；长时间后恢复可能已超时，此时应明确建立新运行，不声称无限续跑。

没有委派 cgroup 时，只能控制已知 POSIX 进程组，不能保证主动逃逸的子孙进程已经终止。写入恢复必须由用户核对；没有远程系统回执时不推断外部动作成功。自动供应商账单硬限额、跨机 Worker、多租户和外部自动补偿不在首版范围内。

## 验证

npm run check 包含类型检查、Node 测试和前端构建。新增 tests/adaptive-release-regressions.test.ts 覆盖任务门槛、跨运行互斥、工件篡改、晚到评估结果、阶段证据、新 Worktree 初始化、真实本机程序停止、现场接纳、运行配置与预检；协议夹具不使用真实供应商凭据或付费模型。

目标机仍需执行：AI_WORK_OS_SMOKE_CONFIRM=1 npm run smoke:adaptive:linux；OpenCode 使用对应 smoke:opencode:linux。还需真实 cgroup 委派、OOM、失联/重启、MCP 权限与浏览器完整操作验收。不得将协议夹具通过写成真实模型验收完成。

本次检查结果：npm run check 通过；142 项测试中 135 项通过、7 项 Windows 专属跳过项。该记录不等同于真实付费模型、目标机 cgroup 或最终浏览器验收。
